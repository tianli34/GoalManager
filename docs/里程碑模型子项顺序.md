## 一、结构抽象：一个开关即可

无需设计子项依赖网（DAG/甘特图），只在「里程碑」容器层级增加属性 **执行模式（Execution Mode）**：

- **并列（Parallel）**：所有子项同时激活，无先后。
- **串行（Sequential）**：按列表顺序，前项达成 100% 后项才激活。

**混合场景**用递归实现「阶段式」：顶层设串行（阶段1→2→3），每个阶段内部设并列。结构简单，可覆盖绝大多数需求。

## 二、状态流转：软锁定优于硬锁定

串行下子项生命周期：`待解锁 Locked` → `进行中 Active` → `已完成 Completed`。

- **视觉聚焦**：高亮第一个未完成子项为「当前聚焦」，后续置灰折叠（GTD Next Action）。
- **软锁定**：`待解锁` 默认隐藏打卡/录入入口；允许用户手动「提前开始」强制转为 Active，系统允许同时存在多个 Active。

## 三、各原子模型作为串行子项的完成判定

- **完成型 / 主观型**：点击完成，或主观进度拉满后确认达成，即解锁下一项。
- **累积型**：∑Δ ≥ target 自动完成。若后续负增量使进度回退，**已解锁不回退锁定**，仅在当前项显示异常警告。
- **指标达成型（From→To）**：指标会波动回退。必须引入**固化/归档（Freeze）机制**——按规则判定达标（如连续3次达标）后状态锁定为已完成，停止接收新读数或新读数不影响完成状态，避免串行链反复横跳。

## 四、进度与配速

**总进度**（与顺序无关）：
Total Progress = Σ(子项进度ᵢ × 权重ᵢ)
权重默认平分，可用户指定，或串行模式下按预计耗时天数自动分配。

**配速（Pacing）**（顺序影响巨大，以总30天、A/B/C 等权重为例）：

- **并列**：三者共享 30 天，A 的日配速分母为 30。
- **串行**：按权重隐式切分时间线，A=1~10天、B=11~20、C=21~30。第5天时 A 的预期进度为 **50%**（而非 16.7%）。
- **动态挤压**：A 延至第15天完成，B、C 仅剩15天（各7.5天），B 激活时日配速自动上调，传递延期紧迫感。

## 五、落地建议

**数据结构**（Milestone 子项关联表）：
```json
{
  "goal_id": "parent_01",
  "execution_mode": "SEQUENTIAL",  // PARALLEL | SEQUENTIAL
  "children": [{
    "child_goal_id": "sub_01",
    "sort_order": 100,        // 串行下决定激活顺序
    "weight": 1.0,
    "is_required": true,
    "status_override": null   // 指标型固化 / 串行提前激活
  }]
}
```

**UI 区分**：
- 并列：独立圆圈/方框（Checkbox）。
- 串行：数字编号①②③ + 左侧竖向连接线（Stepper），已完成实线、未解锁虚线。
