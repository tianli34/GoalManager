## 一、核心领域对象（数据模型）

| 对象 | 关键字段/职责 | 备注 |
|---|---|---|
| **Goal（目标）** | title, why, 达成条件(successCriteria), mechanism(机制), lifecycle(生命周期), startDate?, dueDate?, domain/tags[], parentGoalId?(仅一个), weight?, isRequired?(作为子项时), 原始量(当前值/目标值/起始值) | 子目标也是 Goal，同一套机制 |
| **UpdateRecord（更新记录）** | goalId, timestamp, type(进度推进 / 配置变更 / 重新打开 / 状态变更), 读数/增量/自评值, note, attachments[], 变更原因 | 配置变更与真实推进必须区分 |
| **Commitment（承诺）** | goalId, timeWindow(start,end), 意向表达(按机制自然语义), status(进行中/已兑现/已调整/已取消), 历史变更记录 | 不是目标，不构成树 |
| **Review（复盘）** | timeWindow, 关联 goalIds, 三个问题答案, decision(继续/调整/暂停/结束), nextStep? | 产物是 decision |
| **InboxItem（收集箱）** | text, createdAt, 处理结果(转为新目标/并入已有目标/舍弃) | 不要求机制、日期；不参与任何统计 |

### 枚举定义

```text
Mechanism: COMPLETION(完成型) | CUMULATIVE(累积型) | METRIC(指标达成型) | SUBJECTIVE(主观/动态型) | MILESTONE(里程碑型)

Lifecycle: PENDING(待开始) | ACTIVE(进行中) | PAUSED(暂停) | COMPLETED(已完成) | TERMINATED(已终止)

AttentionSignal(关注信号, 非状态): NO_RECENT_UPDATE | POSSIBLE_STALL | DATE_RISK | INSUFFICIENT_DATA

ReviewDecision: CONTINUE | ADJUST | PAUSE | END

RecordType: PROGRESS | CONFIG_CHANGE | REOPEN | LIFECYCLE_CHANGE
```

### 维度必须正交（不要做成层级）
- 机制、生命周期、时间范围、领域/标签、关注信号 五个维度互相独立。
- **禁止**默认建立「人生→年→季→月→周→日」目标层级；周/季度只是承诺与复盘的时间窗口参数。
- 同一目标可同时出现在周视图和季度视图，靠**查询过滤**实现，不复制数据。
- `isArchived` 是独立布尔字段，不等于 COMPLETED / TERMINATED。
- `isOverdue` 是派生计算（now > dueDate），不写入生命周期。

---

## 二、里程碑 / 树结构约束

- 子项 = Goal，可递归，可用任意机制。
- 每个 Goal **最多一个** `parentGoalId` 用于进度上卷（防重复计算）。
- 领域、季度、周计划**不能**作为父节点。
- 父级进度 = 子目标加权推导，**不允许直接写父级百分比**（父级进度为只读派生值）。
- 完成判定依据 `isRequired` 子项是否全部完成，而非加权百分比 ≥100%。
- UI 只渲染当前层，不默认展开整棵树。

## 三、进度计算规则

### 双轨：时间消耗线 vs 计划进展线
```
timeElapsedRatio = (now - startDate) / (dueDate - startDate)   // 需要 start 和 due 都存在，否则不计算
plannedProgress  = 依机制与计划假设计算，可能为 null
```
无日期目标：不计算时间线，不强制要求填日期。

### 各机制计算/展示规则

| 机制 | 进度值 | 时间参照处理 | 完成判定 |
|---|---|---|---|
| COMPLETION | 0 或 100 | 只显示剩余时间；**不**做"落后"判断 | 用户标记完成 |
| CUMULATIVE | (当前累计-起始)/(目标-起始)，**允许 <0 或 >100** | 默认线性配速，UI 标注"计划假设" | 累计达到目标值 |
| METRIC | 当前读数相对目标；保留全部历史读数 | 线性线仅参考；重点计算趋势、波动、**稳定达标**（需观察窗口参数） | 稳定达标规则满足，而非一次读数到 100% |
| SUBJECTIVE | 用户自评值，系统**永不自动修改** | 时间线与自评并排展示，不输出"落后 X%" | 用户判断 |
| MILESTONE | 子目标加权上卷（只读） | 子项有计划日期时上卷计划进度，否则只显示时间消耗 | 必需子项全部完成 |

### 三条底层不变量
1. **进度 ≠ 完成判定 ≠ 生命周期**，三者分别存储/计算。
2. COMPLETED 目标**不自动重开**：后续读数回退不改变 COMPLETED；需显式 `REOPEN` 记录。
3. 始终持久化并展示**原始量**（读数、累计、增量），百分比仅为派生展示；不截断负值和 >100%。

### 禁止项
- 不计算跨目标的全局"人生总进度"/平均完成率；权重只在同一父目标下有效。
- METRIC 的"覆盖式更新"= 覆盖 `currentValue`，**不删除**历史读数记录。

## 四、承诺（Commitment）规则

- 承诺的量按机制自然语义存储，不强制统一为百分比：
  - CUMULATIVE：目标增量（如 +500）
  - COMPLETION：布尔
  - SUBJECTIVE：自评推进 N 点
  - MILESTONE：指定子目标 id 完成
  - METRIC：仅作"结果期望"，未达不解读为投入不足
- 边界规则：
  1. 承诺未兑现 → 不改变目标 lifecycle，不标记失败。
  2. 调整/取消承诺 → 保留历史（追加记录，不覆盖删除）。
  3. 修改目标值/权重/范围 → **不得**使旧承诺自动变为"已兑现"（承诺兑现判定应基于承诺创建时的快照或按真实推进量计算）。
- 首页聚焦数量：建议软性引导，**不做硬性上限校验**。

## 五、停滞检测 / 关注信号逻辑

三类信号分别判断，各通向一个具体操作：

| 信号 | 触发条件 | 推荐动作按钮 |
|---|---|---|
| NO_RECENT_UPDATE | 距上次记录 > 阈值 | 更新 / 确认无变化 |
| POSSIBLE_STALL | 有记录但预期变化未发生 | 写说明 / 检查计划 |
| DATE_RISK | 截止临近且计划进展明显落后 | 调整范围 / 日期 / 承诺 |

机制相关的排除规则：
- COMPLETION 长期 0% → 不触发 POSSIBLE_STALL。
- METRIC 需达到最小观察窗口样本数，否则输出 INSUFFICIENT_DATA（"尚无法判断"）。
- SUBJECTIVE 不由系统改进度，只能邀请用户自评。
- lifecycle = PAUSED → 不产生任何提醒。
- 所有提醒必须附带操作入口：更新 / 确认 / 调整 / 暂停 / 结束。

## 六、复盘最小闭环

```
Review {
  q1_whatHappened: text
  q2_stillWorthOriginalPlan: text/bool
  q3_decision: CONTINUE | ADJUST | PAUSE | END
  nextStep?: string   // 仅一条简短文本，不引入任务模型
}
```
闭环顺序：记录事实 → 关注信号 → 复盘 → 决定 → 生成下一期承诺。

---

## 七、正反馈（首版）

- 三类信号基于真实记录派生，**不做**积分/等级/连续签到：
  - 动量：近期有意义的推进、从停顿恢复
  - 成就：完成的目标、达成的子项、兑现的承诺
  - 意义：关联 Goal.why
- 回退、调整可展示但不计入"增长"。

## 八、信息架构（导航/路由）

```
/now        当下：本期承诺 + 重点目标 | 需要关注(信号列表) | 收集箱入口
/goals      目标：按 lifecycle 分组(进行中 / 待开始+暂停 / 已完成+已终止) + 领域/标签筛选 + 树结构
/review     回顾：本周期变化 | 周期复盘 | 历史复盘与调整 | 达成记录
全局 FAB    捕获想法 / 更新已有目标
/settings   备份、导入导出、偏好
```

- `/now` 只渲染筛选后的少数目标和带解释的信号，不渲染全量进度环、统计总分、逾期红色长列表。
- 目标详情共用骨架：定义/why → 达成条件 → 状态与进度解释 → 日期与时间参照 → 当前承诺 → 时间线 → 子目标(仅 MILESTONE)。只有进度区组件和记录输入组件按机制切换。

---

## 九、存储 / 导出 / 本地优先

- 无账号可用；核心读写不依赖网络；同步作为可选增强层。
- 本地备份/恢复路径必须在同步上线前就存在（换机、丢机场景）。
- 导出内容必须完整覆盖：
  - 目标定义 + 达成规则 + 机制参数
  - 全部 UpdateRecord（含原始读数、附件）
  - 父子层级 + 权重 + isRequired
  - Commitment、Review、配置变更历史
- 提供两种导出格式：可读格式（如 Markdown/HTML）+ 可完整恢复的结构化格式（如 JSON）。

## 十、首版范围（MVP 边界）

**做**：五种机制语义正确；轻量更新入口；进度与历史可解释；简单周期承诺；三问复盘；完整导出/恢复。

**延后**：预测算法、复杂自动化停滞诊断、成就体系、复杂项目可视化、同步/协作。

**不做**：完整待办/日程、连续打卡习惯系统、多层级 OKR、社交排行榜、知识库。

**北极星候选指标**：完成"记录→信号→复盘→决定"闭环的周期数，而非日活/打卡次数/完成率。
