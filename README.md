# 北极星 — 首版 MVP

一个**本地优先**的目标管理应用（Flutter，手机端形态）。

它不是待办清单，也不做连续打卡。它的核心主张是：

> 目标要能被**解释**：进度怎么算出来的、为什么提醒你、这周期到底发生了什么变化。

设计依据全部来自 [`docs/`](docs/) 里的四份文档，本 README 只说明「首版落地成了什么」。

---

## 快速开始

```bash
flutter pub get
flutter test          # 领域层单测（进度 / 里程碑 / 信号 / 承诺 / 导出）
flutter run           # 手机 / 桌面
flutter build web     # Web（数据存在 localStorage）
```

> 依赖只有两个官方插件：`shared_preferences`（本地持久化）与 `path_provider`（备份文件目录）。
> 其余全部是 Flutter SDK 自带能力，没有引入状态管理 / 数据库 / 图表库。

## 首版做了什么

| 模块 | 状态 | 说明 |
|---|---|---|
| 五种目标机制 | ✅ | 完成型 / 累积型 / 指标型 / 主观型 / 里程碑型，语义各自独立 |
| 进度的双轨展示 | ✅ | 时间消耗线 + 计划进展线，并排展示，不混为一个分数 |
| 可解释性 | ✅ | 每个进度都有一个「这个值是怎么算出来的」折叠区 |
| 关注信号 | ✅ | 久未更新 / 疑似停滞 / 日期风险 / 尚无法判断，每条都带操作入口 |
| 周期承诺 | ✅ | 按机制的自然语义记录，未兑现不判失败，改配置不会让旧承诺自动兑现 |
| 三问复盘 | ✅ | 发生了什么 → 还值得吗 → 决定（继续/调整/暂停/结束） |

| 本地备份 | ✅ | 无需账号、无需网络；数据损坏时另存原始内容，不静默丢弃 |

## 五种机制的实现要点

| 机制 | 输入 | 进度 | 完成判定 | 时间参照 |
|---|---|---|---|---|
| 完成型 | 一次「完成」（可撤销） | 0 或 100 | 你标记完成 | 只显示剩余时间，**不做落后判断** |
| 累积型 | 增量 Δ（可为负） | (当前−起始)/(目标−起始)，允许 <0 或 >100 | 累计量达到目标值 | 线性配速（标注为「计划假设」）+ 每日还需 |
| 指标型 | 读数（覆盖式，历史全留） | 同上，方向通用 | **连续 N 次读数达标**（可配置） | 线性仅作参考，重点看近期斜率外推的预计达成日 |
| 主观型 | 动态文本 + 手动自评 0~100% | 等于最新自评值 | 你判断 | 时间线并排展示，**不输出「落后 X%」** |
| 里程碑型 | 子项（任意机制，递归） | 子项加权上卷（**只读**） | 全部「必需」子项完成 | 子项有计划日期时上卷，否则只显示时间消耗 |

三条底层不变量（代码里到处都有对应实现）：

1. **进度 ≠ 完成判定 ≠ 生命周期**，三者分别存储与计算；
2. 已完成的目标**不会自动重开**，读数回退也不改变它，必须显式「重新打开」并写原因；
3. 始终持久化并展示**原始量**（读数、累计、增量），百分比只是派生展示，不截断负值 / 超额。

配置变更与真实推进在**时间线里是两种记录**，不会混在一起。

## 里程碑的串行模式

- 执行模式只用一个开关：**并列 / 串行**，混合场景靠递归（顶层串行 = 阶段，阶段内并列）。
- 串行用**软锁定**：待解锁项默认隐藏录入入口，但可以「提前开始」，允许同时存在多个进行中。
- 已完成项如果原始量回退（例如累积型被减回去），只标记「已完成后回退」警告，**不回退解锁**。
- 指标型在达标后会**固化**（可手动触发），停止接收新读数，避免串行链反复横跳。
- 配速会**动态挤压**：前一项延期后，后面的子项共享剩余时间，日配速自动上调。

## 信息架构

```
/now      当下：本期承诺 + 重点目标（软性引导 3~5 个）+ 需要关注 + 收集箱入口
/goals    目标：按生命周期分三组 + 领域/标签筛选 + 树结构（只渲染当前层）
/review   回顾：本周期变化 → 三问复盘 → 历史复盘 → 达成记录
全局 FAB  捕获想法 / 更新已有目标
/settings 备份导出（JSON / Markdown）、导入恢复、信号阈值、清空数据
```

## 代码结构

```
lib/
  core/          日期窗口（周/季只是查询参数，不是目标层级）、id
  data/
    models/      Goal / UpdateRecord / Commitment / Review / InboxItem / AppData
    storage/     KeyValueStore 抽象 + shared_preferences 实现 + 损坏保护
    export/      JSON / Markdown 导出与解析（file_writer 用条件导出切 Web）
  domain/        ★ 纯 Dart，无 Flutter 依赖，可单测
    progress.dart     五种机制的进度、配速、完成判定、历史回放
    milestone.dart    串行/并列、软锁定、时间线切分与挤压
    signals.dart      四类关注信号与各自的排除规则
    commitments.dart  按机制自然语义的兑现判定（基于创建时快照）
  state/         AppState（ChangeNotifier）：所有写操作的唯一入口 + 示例数据
  ui/            四个页面 + 按机制切换的进度区 / 记录输入区
test/            domain 层单测 + 导出往返 + widget 冒烟测试
```

维度正交原则在代码里的体现：`mechanism`、`lifecycle`、时间范围、`tags`、`isArchived`
是互相独立的字段，只有 `parentGoalId` 构成树，且**每个目标最多一个父节点**。

## 备份与恢复

- **JSON**：完整覆盖目标定义 + 达成规则 + 机制参数、全部 `UpdateRecord`（含原始读数）、
  父子层级 + 权重 + `isRequired`、`Commitment`、`Review`、配置变更历史。
- **Markdown**：给人看的同一份内容，含进度解释与时间线。
- 导入时会校验 `schemaVersion`，任何解析失败都会给出可读错误并保留原数据。
- 读取失败时，原始数据会被另存一份到 `goal_manager.data.broken.*`，**不会静默丢数据**。

## 首版不做（明确延后）

- 预测算法、复杂自动化停滞诊断
- 成就体系 / 积分 / 等级 / 连续签到
- 复杂项目可视化（甘特图、依赖网）
- 同步与协作
- 完整待办/日程、多层级 OKR、社交排行榜、知识库

北极星候选指标：跑完「记录 → 信号 → 复盘 → 决定」闭环的**周期数**，而不是日活或完成率。
